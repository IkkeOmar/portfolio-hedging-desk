# Security policy

## Scope

This repository is a **research and learning artifact**. It runs a paper
broker. It has no broker integration, no order routing, no credential
handling and no live-trading path.

## No live trading

The execution layer is `src/execution/paper.py`. It refuses to run live
unless the `LIVE` environment flag is explicitly set, and nothing in this
repository, its scripts, its tests or its CI sets it. If you fork this and
wire a real broker, you own that decision and its consequences entirely.

**Do not point this at real money without reading the source first.**

## What the desk is allowed to do

By design, and enforced in code rather than by convention:

- **Only the Risk seat can approve an order.** No other seat can produce an
  `OrderIntent`, and the execution adapter refuses an intent without a valid
  Risk signature.
- **Fail-safe by construction.** The default state of every gate is "no". A
  crashed seat, a failed write or a confused adapter cannot produce an
  order.
- **The kill switch is a file on disk.** It survives a crash, a reboot, and a
  human who needs the desk stopped immediately. Create it and the desk
  refuses to trade until you remove it.

## Reporting a vulnerability

If you find a bug in the risk controls, in the look-ahead logic, or in the
cost model, please open an issue or email the maintainer. Those three areas
are the ones where a bug turns into a loss, and they are the ones we most
want to hear about.

For anything involving credentials, keys or network access in a fork you
built, report it as a bug in **your** fork. This repository does not handle
secrets and has no network surface of its own.

## Data

The bundled market data is generated by this repository's own code
(`src/data/synthetic.py`). It is a deterministic test fixture, not market
data, and it is covered by the repository's MIT licence.

If you point the desk at a real data source, that source's terms and its
rate limits are yours to respect.
